### Core activity

Write notebook activities in this repeated form:

1. **Predict:** What do you expect, and why?
2. **Run:** Execute a small complete example.
3. **Explain:** What changed? What are the shape, units, or assumptions?
4. **Modify:** Change one scientifically meaningful element.
5. **Check:** Compare with a known value, plot, assertion, metadata field, or peer explanation.

### Accessibility and inclusion check

- All plots use readable labels and color choices that do not carry meaning through color alone.
- Instructions are available in writing as well as spoken.
- The exercise does not rely on public speed or prior jargon.
- Keyboard-only or alternative access has been considered.
- Students can rejoin from a checkpoint after a setup problem.

### Materials QA

- [ ] Restart kernel and run all cells top-to-bottom.
- [ ] Preflight each live acquisition on the classroom network without relying on browser state or
  instructor credentials.
- [ ] Run every downstream step from the documented local recovery file with the network disabled.
- [ ] Run from the documented directory using only relative project paths.
- [ ] Confirm every data variable's units, dimensions, provenance, and QC meaning.
- [ ] Confirm expected outputs and random seeds.
- [ ] Test on supported operating systems/environment.
- [ ] Time the core path with a novice proxy.
- [ ] Mark the first block to cut if time is short.
- [ ] Release a completed reference notebook and static HTML export.
- [ ] Release concept notes with formulas, assumptions, worked examples, and common errors.
- [ ] Check source attribution and license obligations.
- [ ] Remove outputs that leak paths, usernames, credentials, or unpublished data.
